# ملخّص المشروع — خطّ إنتاج المخطوطات العربية

> هذا الملف ملخّص تنفيذي شامل للمشروع باللغة العربية. مرجعيته الحالية تعتمد على
> الكود الفعلي و`AGENTS.md` و`docs/PROGRESS.md`. أما `README.md` و
> `docs/PROJECT_SUMMARY.md` فهما تاريخيان ويصفان تخطيطًا قديمًا (مسطّحًا) لم يعد دقيقًا.

---

## 1) الهدف من المشروع

تحويل **المخطوطات العربية المطبوعة والمشكوكة (PDF)** إلى نص رقمي مهيكل، مع **الحفاظ
على التشكيل (الحركات) قدر الإمكان**. حالة الاختبار الأساسية هي كتاب ***عمود النسب***
("عمود النسب") — 113 صفحة من الشعر الكلاسيكي المشكول بالكامل مع تعليق نثري في الهوامش
وتحت الأبيات. تمت معالجة مخطوطة ثانية، ***لمعة النسب***، كحالة إصلاح ToUnicode.

**المبدأ الحاكم: `OCR ≠ Editing`.** النظام يستعيد ما هو *موجود على الصفحة*، ولا
يعيد كتابته في عربية "أفضل". أي تحسين يُكتب في طبقة منفصلة ولا يُمسس طبقة الدليل
الأصلية `raw_text/` أبدًا.

---

## 2) كيف يعمل الـ pipeline

الكود الفعلي في حزمة `src/pipeline/` (وليس تخطيطًا مسطّحًا)، ويستورده `main.py`
مباشرة. الممر الأساسي يُنفَّذ صفحة-بصفحة:

```
data/input/  (PDF أو صور)
   │
   ▼  ingestion          تحميل كل صفحة + رسمها صورة (200 DPI)
   ▼  preprocessing      deskew → CLAHE → denoise خفيف (ترتيب ثابت)
   ▼  layout_detection   إطار المحتوى + فاصل الشعر/النثر + الأسطر + الـ gutter
   ▼  ocr_engine         PaddleOCR لكل سطر على حدة + كاش SQLite
   ▼  vision_fallback    تصعيد الأسطر منخفضة الثقة لـ LLM بصري (اختياري)
   ▼  output             حفظ صفحة-بصفحة + إعادة بناء المستند الكامل
   ▼
data/output/<الوثيقة>/raw_text/   (طبقة الدليل — لا تُكتب فوقها أبدًا)
```

ثلاث مراحل لاحقة **منفصلة ولا تلمس `raw_text/`**:

- **مرحلة التصحيح** (`review_manuscript.py` + `text_correction_engine.py`) — اختيارية،
  تكتب في `corrected_text/` فقط.
- **تصحيح الأسماء** (`scripts/vault_vote_correct_names.py` و`genealogy_crossref.py`) —
  تنتج طبقة `vault_corrected_text/` وهي الطبقة التي يقيس عليها الـ benchmark.
- **التقييم** (`evaluation/`) — تنظيف GT ومواءمته ثم قياس CER/WER/DER.

## 4) ما تم إنجازه (الخط الزمني)

1. **الأساس (ما قبل git + specs 001–004)** — تنظيف الـ GT (620 بيت)، أول قياس حقيقي
   (CER 25.0%)، إصلاح إعادة بناء `full_manuscript.txt`، وبوابة كثافة الحبر.
2. **إعادة الهيكلة** — نقل الكود إلى حزمة `src/pipeline/` (commit `2587731`).
3. **جولة القياس (specs 005–022)** — قِيس كل مكوّن، و16 من 22 spec سلبي أو مختلط،
   وكُلّها سُجِّلت بدل طمسها.
4. **عملية الـ vault** — فهرس 227 اسمًا للقراءة فقط، مراجعة كل الـ 56 صفًا يدويًا →
   **34 تصحيحًا مطبّقًا**، ثم **تراجع عن 4** (عقبة→عتبة، حام→سام) بعد تناقض مع GT،
   بقي **30**. الطبقات: 6 مؤكدة بالـ GT / 4 مراجعة فقط / 20 خارج نطاق GT.
5. **خطة الإغلاق + تقسيم الـ commits** — 7 commits قابلة لـ `git bisect`، كلها تمر
   `verify_all.py` منفردة.
6. **Phase 4 (الحالي)** — تقديم 118 صفًا في طابور المراجعة اليدوي؛ مسجَّل منها
   **47 سجلًا (20 full_line / 27 partial)**. آخر commit: تسجيل p044_08 كبيت كامل
   وتصحيح p029_00 إلى "القلادة".

## 5) ما تم تجربته ورفضه (بالأدلة)

كل هذه السبل قِيسَت ورُفضت — ولا يجب إعادة فتحها:

| المسلك | النتيجة | سبب الرفض |
|---|---|---|
| Surya لتقسيم الأسطر | 27.0% → 26.5% | ضوضاء؛ التقسيم ليس عنق الزجاجة |
| رفع الـ DPI إلى 300 | 26.8% → 25.3% | غير معتبر إحصائيًا (p≈0.16، CI يعبر الصفر) |
| نموذج PaddleOCR v3 | CER +3.9pp أسوأ | استرجاع التشكيل انهار 82.4% → 8.6% |
| Qari-OCR (VLM) | recall 5.3% | يشطب التشكيل ويفشل كليًا في صفحات |
| Fine-tuning (مرتين) | 28.6%→26.8% ثم 33.1%→32.4% | التشكيل لم يتحرك أبدًا |
| Diacritic-weighted CTC loss | مطابق تمامًا للـ plain | وزن العينة لا يحمل معلومة الموضع |
| استرجاع التشكيل (tashkeel) | ظاهريًا +3.6 | 87% من علاماته تخالف الـ vault |
| إصلاح التشكيل الصرفي | net **−50** | style mismatch مع `calima-msa-r13` |
| البوابة الصرفية لتخطي المراجعة | 0/45 صفحة قابلة للتخطي | rho = −0.112 (علاقة صفرية) |
| Backends بديلة مجانية | أسوأ من Paddle | hallucination لا قراءة |

**الخلاصة:** كل الروافع الهندسية أُغلقت بالقياس. الـ fine-tuning line مغلقة بشرط
إيقاف مُلزم (نفيان متتاليان).

## 6) ما هو مفتوح الآن (مرتّب بالقيمة)

1. **إنهاء طابور المراجعة الـ 118** — زراعة `full_line` gold من 20 إلى ~50 سجلًا؛
   هذا هو **بوابة الدقة الوحيدة التي لا تزال قابلة للتحريك بالجهد البشري** (يحجب
   Phase 3: بوابة tashkeel المقيدة ببحث الـ vault المباشر).
2. **التحقق من الـ 20 تصحيحًا خارج نطاق GT** — 67% من التصحيحات المطبقة، صفر فحص
   آلي، ومعدل خطأ مراجعة مُقاس ~8% (كلا الخطأين المُتراجَع عنهما أتيا من هذه الطبقة).
3. **مراجعة الـ escalations فائقة التعديل** — هلوسات فريدة على قصاصات ضعيفة تمر من
   كل البوابات الحالية دون كشف.
4. **مهام نظافة معلّقة** — `README.md` لا يزال يصف التخطيط المسطّح المحذوف ويسرد
   Claude/`ANTHROPIC_API_KEY` المُزالين؛ و`verify_jiwer.py`/`verify_cer_harness.py`
   ناجحة لكن غير موصولتين في `verify_all.py`، وعدد الاختبارات المُثبَّت (368) أصبح
   باليًا مقابل 400 مُصرَّح بها.

## 8) كيفية التشغيل والتحقق

```bash
myenv/bin/python verify_all.py                    # كل فحوص الإغلاق دفعة واحدة
myenv/bin/python main.py                          # كامل input/
myenv/bin/python main.py --start 24 --end 26      # نطاق تجريبي
myenv/bin/python review_manuscript.py --document "عمود النسب نسخة 2"   # مرحلة التصحيح
```

**قيد الأجهزة:** Dell G15 / Void Linux / **GTX 1650 بـ 4GB VRAM فقط** / Python 3.11.16
(يُسمح بـ `myenv/bin/python` فقط). لذلك `segment_batch_size = 16` حد عملي.

**تحذير:** `.env` يحتوي مفاتيح API حقيقية — يُمنع قراءته أو عرضه في أي diff.

## 9) الخلاصة

المشروع **وصل إلى سقف reconnaître مُقاس ومُسلَّم به**. كل مكوّن في الـ pipeline قِيس
بالأرقام، وكل رافعة رُفضت بالدليل لا بالتقدير. ما تبقى ليس هندسة بل **مراجعة بشرية
ممنهجة**: إنهاء طابور الـ 118 صفًا لزراعة gold corpus هو العمل الوحيد الذي يحرّك
مؤشرات الدقة الآن. وأهم أصول المستودع ليست الكود، بل **القياسات التي قالت "لا"**.
